# 2026-09-05

## Exercise search now matches muscles, not just names

Ben pointed at the Log > Train > Exercises screen: typing in the search box only matched exercise
names, so searching "glutes" or "triceps" returned nothing even though most of the 96 seeded
exercises carry a `muscles` string that says exactly that. Every card on that list already prints
the muscles under the name — searching for what you can see on screen should work.

Plan > Exercises had already been widened to search `name` + `movementPattern` + `muscles`; Log and
the routine builder's exercise picker were still name-only. So this was a consistency gap as much as
a missing feature — the same list, searched three different ways depending on where you opened it.

### The fix

Two files, same predicate as `Plan.jsx` already uses:

- `src/pages/Log.jsx` — the Train > Exercises filter now ORs name, movement pattern and muscles.
- `src/components/routines/RoutineModal.jsx` — same, inside the picker's existing `.filter()` chain
  (kept as an early-return block so the category and pattern filters above it are untouched).

Guards on `movementPattern` and `muscles` because both are optional on user-created exercises.

### Verified

`npm run build`, `npm test` (334 pass) and `npm run lint` (0 errors) all clean. The running app can't
be checked from a cloud container — it gates on Firebase sign-in and the sandbox proxy blocks the
auth call — so the predicate was instead run directly against `defaultExercises.js`: "glute" → 21
matches, "triceps" → 13, "peroneals" → 3 (Ankle Circles, Ankle Alphabet, Single Leg Calf Raise), and
an empty search still returns all 96. Category + search still compose ("core" + "glute" → Plank,
Side Plank, Bird Dog).

Merged straight to main on Ben's instruction.
