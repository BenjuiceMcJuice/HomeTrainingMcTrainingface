## Exercise search now matches muscles, not just names

Ben pointed at the Log > Train > Exercises screen: typing in the search box only matched exercise
names, so searching "glutes" or "triceps" returned nothing even though most of the 96 seeded
exercises carry a `muscles` string that says exactly that. Every card on that list already prints
the muscles under the name — searching for what you can see on screen should work.

Plan > Exercises had already been widened to search `name` + `movementPattern` + `muscles`; Log and
the routine builder's exercise picker were still name-only. So this was a consistency gap as much as
a missing feature — the same list, searched three different ways depending on where you opened it.

### The fix

Two files, same predicate as `Plan.jsx` already uses:

- `src/pages/Log.jsx` — the Train > Exercises filter now ORs name, movement pattern and muscles.
- `src/components/routines/RoutineModal.jsx` — same, inside the picker's existing `.filter()` chain
  (kept as an early-return block so the category and pattern filters above it are untouched).

Guards on `movementPattern` and `muscles` because both are optional on user-created exercises.

### Verified

`npm run build`, `npm test` (334 pass) and `npm run lint` (0 errors) all clean. The running app can't
be checked from a cloud container — it gates on Firebase sign-in and the sandbox proxy blocks the
auth call — so the predicate was instead run directly against `defaultExercises.js`: "glute" → 21
matches, "triceps" → 13, "peroneals" → 3 (Ankle Circles, Ankle Alphabet, Single Leg Calf Raise), and
an empty search still returns all 96. Category + search still compose ("core" + "glute" → Plank,
Side Plank, Bird Dog).

Merged straight to main on Ben's instruction.

## Dashboard widgets: the icon column becomes a corner marker

Ben, on a phone screenshot of the Dashboard: *"The widgets have a lot of white space in the left hand
side… can we make better use of the width. Also the icon for each widget whilst nice is ok but could
each widget maybe be marked in a more space efficient manner perhaps (triangle / corner marker
maybe?) with more meaningful/relevant icon?"*

### What was actually wrong

Every card opened with a `w-10 h-10` circular icon in a flex column of its own — 40px plus a 12px
gap. Where `WidgetShell` sat relative to that column is what decided the damage, and it was not the
same on any two cards:

- **Weight, gym, cardio, boulder, rope** — the shell sat *beside* the circle as `flex-1`, so the
  52px indented the **entire card**. Window chips, bar charts, trend lines, captions: all of it
  pushed right, on a 393px phone. That is the "even more wasted space" in the screenshot.
- **Alcohol, training load** — the circle sat *inside* the header only, so the body ran full width
  but the header did not. The card read with two different left edges, and under the vertically
  centred circle sat a tall blank gutter beside the week strip and the growth fact.
- **Coach tip** — a 16px inline icon costing 26px, which the tip text then wrapped against.
- **Activity calendar** — no icon at all. It was already the shape everything else needed to be.

### The fix

`components/dashboard/WidgetCorner.jsx`, new: an `aria-hidden` right-triangle filling the card's
top-left corner, with the widget icon rendered **inline at the head of the headline row** so it
appears inside the wedge without holding a column open. Everything that is not the headline now
starts at the card's own `px-4`. One left edge per card, on all nine.

Three things that were got wrong first and are worth recording:

1. **Painted from the pale named tints** the icon circles used (`#edfaf2`, `#eef1ff`). On white they
   were near-invisible — the mark read as a smudge. Now `accent + '1f'` with a 30%-accent hairline
   down the hypotenuse, which is what makes it a corner rather than a wash.
2. **Level cards took the level colour** for the wedge, so an *Advanced* boulder card had a blue
   corner around an orange mountain. Corner colour follows icon colour now; the level is already
   spelled out in the word beside it.
3. **`overflow: hidden` on the card** was the obvious way to clip the wedge to the 16px radius and
   is wrong — `BarTimeline` draws peak labels that escape their own box. The wedge clips itself.

Icons changed only where the old one was not saying much: cardio `Activity` → `HeartPulse` (the
generic squiggle for the one card that is literally about heart rate), rope `Mountain` →
`MountainSnow` (boulder and rope were the same glyph in two colours). The calendar gained
`CalendarDays` so every widget is marked the same way. Weight, gym, coach and the dynamic
alcohol/training-load icons are unchanged.

`LevelCard`'s `icon` prop changed from a ready-made element to a component plus an `accent`, since
the corner needs the colour too. Aliased to a capitalised local inside the body (`const Icon = icon`)
to match `FlagCard` in `Coach.jsx` — there is no `eslint-plugin-react` here, so a capitalised
*parameter* used only in JSX trips `no-unused-vars` where a capitalised *variable* does not.

### Files

`WidgetCorner.jsx` (new), `WeightCard`, `GymStatsCard`, `CardioStatsCard`, `LevelCard`,
`AlcoholFreeCard`, `TrainingLoad`, `CoachTip`, `ActivityCalendar`, `pages/Dashboard.jsx`.
`docs/specs/betalog_widget_system_spec.md` gains a "The corner marker" section and an amended
anatomy diagram.

### Verified

`npm run build`, `npm test` (334 pass) and `npm run lint` (0 errors, 15 warnings — the pre-existing
baseline) all clean.

**Seen running.** The app itself gates on Firebase sign-in and the sandbox proxy blocks the auth
call, so the widgets were mounted instead in a throwaway Vite harness — the real components, real
`DataContext`, fake sessions/weights/drinks/goals — and screenshotted in headless Chromium at 393px
with everything expanded, before and after. Confirms the width gain on all nine cards, the corner
legible on white and on the alcohol card's own tint, the icon sitting inside the wedge, and the
whole column ~60px shorter. The harness was deleted afterwards; nothing of it is in the branch.

Branch `claude/widget-layout-spacing-fl20nd`, not merged — this is a visible change to screens that
already work, so it waits for an explicit instruction to release.
