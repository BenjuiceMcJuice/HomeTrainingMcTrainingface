## SDLC re-baselined to two stages

Ben asked to re-baseline the SDLC — "what it is and what it should be" — after the branch model kept
producing "deviations" in the logs.

### What it actually was

The documented `feature → preprod → main` flow **had never run once**. `preprod` points at
`add5889`, which is a commit in `main`'s own linear history dated 2026-08-10 — so the branch was
created by pointing at `main`'s tip and then never used. It never received a merge and was never
merged into `main`. `main`'s history is linear throughout, with no merge commits since 2026-07-12.

So yesterday's two "deviations from the branching model" weren't deviations. Direct-to-`main` is the
only mode this repo has ever had.

### What it is now

Two stages: **feature branch → `main`**. Rewrote `docs/guides/betalog_sdlc.md` and the Branches
section of `CLAUDE.md` to match.

The argument for dropping the middle stage, recorded in the guide so it doesn't get re-litigated:
Cloudflare Pages builds a preview URL for *every* branch, so verification on a real URL already
happens one stage earlier — `preprod` added no capability. A staging branch earns its place when
several people land work independently and a release needs a batching point. What actually protects
production here is the pre-merge checklist plus Cloudflare's instant rollback, and neither needs an
extra branch. Noted that if the third stage ever comes back it should come back with CI, or it will
drift the same way.

Also folded into the guide: `npm run lint` in the checklist, the Worker deploy step
(`workers/betalog-calendar/`), and the fact that Firestore rules do **not** ship with a merge to
`main` — a separate `firebase deploy` is required.

### Unmerged work found — one item is a live security gap

`claude/skills-syntax-hZnz6` (2026-06-05, one commit) has been sitting unmerged for two and a half
months and contains security hardening that production still lacks:

- **`friendCodes` enumeration.** Live rules grant `allow read` on `friendCodes/{code}` to any
  authenticated user. `read` covers `list`, so any signed-in user can enumerate every friend code
  and the uid behind it. The branch narrows this to `allow get`, which permits the by-ID lookup the
  feature actually needs and blocks the query.
- **No security headers.** The branch adds `betalog-react/public/_headers` with CSP,
  `X-Frame-Options`, `X-Content-Type-Options` and `Referrer-Policy`. Production has no `_headers`
  file at all.
- Admin check moves from a hardcoded UID to a `centreAdmins/{uid}` lookup.

**Caveat that stops it being a straight merge:** the CSP was written in June, before the feedback
widget (2026-07-12), Cloudflare analytics (2026-08-10) and the calendar Worker (2026-08-19) existed.
As written, `script-src 'self'` and the `connect-src` list would block all three. The rules fix and
the CSP need separating — the rules change is good as-is, the CSP needs its allowlist rebuilt
against what the app loads today.

## Declutter phase 0 — invisible tidy

Both halves of phase 0 from `docs/specs/betalog_ia_declutter_spec.md`.

**Deleted `src/components/dashboard/GoalsWidget.jsx`** (60 lines). Confirmed imported nowhere before
removing, and `grep` is clean afterwards.

**Extracted BMI into `stats.js`.** `BMI_CATS`, `bmiCategory()` and a new `calcBMI(weightKg, heightCm)`
now live in one place. `WeightCard.jsx` and `ProfileTab.jsx` both import them; both previously
carried their own copy of the category table and the loop, in different dialects (`const`/arrow vs
`var`/`function`) but with identical behaviour. The formula itself was inline in both and is now
`calcBMI`.

`calcBMI` returns `null` rather than a number when either input is missing or non-positive, so
callers test the result instead of guarding the inputs — that is what both call sites were already
doing by hand.

**One deliberate behaviour change at an unreachable edge:** a negative weight or height used to
produce a negative BMI and get labelled "Underweight"; it now returns `null`. Not reachable through
the UI, and null is the honest answer.

### Verified

- `npm test` — **114/114** (107 before, plus 7 new in `src/lib/__tests__/bmi.test.js` covering the
  formula, the null cases, each band, and that boundaries are exclusive so 25.0 is Overweight).
- `npm run build` clean; `npm run lint` 0 errors, the same 16 pre-existing warnings.
- **Differential check** against both original inline implementations over every weight 0-200kg and
  height 0-220cm in 0.5 steps — 176,841 pairs, **0 mismatches** on both the BMI value and the
  category label. The refactor is behaviour-preserving.

Not driven in a browser. It is a pure extraction with unit coverage and a differential proof, and
the two call sites render the same values from the same inputs.
