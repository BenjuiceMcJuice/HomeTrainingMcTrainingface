## BTL-B126 — Repeat replaces Project

Ben, with a Dashboard screenshot: *"For climbs logged we have attempt and project. They're basically
the same thing? I was thinking having 'repeat' as an option maybe in-between send and attempt. Eg
today I did a V4 then did it again. I wanna log it but cos I had the moves dialled it felt easier."*
Then, on the recommendation to drop Project rather than keep five buttons: *"Drop and replace.
Build and merge."*

**Why.** Project and Attempt were one outcome under two labels — the guide said so (*"Same as an
attempt for the maths"*), and nothing in stats, pyramid or goals read `project` as its own thing.
Project was also a claim about intent, which the data-honesty spec rules out. Repeat, by contrast,
closes a real honesty hole: without it, sending the same V4 twice logged two V4 sends, and eight laps
of one problem would have owned the grade. The pyramid spec had called this *"the one real gap"*
(§3) since September and settled for no cap because Ben said he would not log repeats; now he can,
and the pyramid ignores them.

**The rule.** A repeat is a clean ascent of a problem already sent. It is a *climb* wherever the
session is described — the climb count, History's *Best* and level pill, the widget bars (a faint
accent segment after the sends, with its own legend entry), the friends feed's *N sent*, the
coach's climb line (*1x V4 repeat (already sent)*). It is never a *send* wherever a send is
evidence of grade — pyramid credit, send-goal evidence, *Best* on the level card, the public profile's
highest send. Two helpers in `stats.js` say which is which: `isSend` (flashed, sent) and `isClean`
(flashed, sent, repeat).

**Files.** `ClimbLogger.jsx` (the buttons, Repeat in a dusky blue between Send and Attempt),
`SessionDetailSheet.jsx`, `stats.js` (`repeats` per grade and in total; `hardestGrade` reads clean
ascents), `pyramid.js` (`repeats` per tier, never credited), `GradeChart.jsx`, `coach.js`,
`storage.js` (`project` → `attempt` on load, beside `fell`), `types.js`, the guide and the
explainer, the data model, the pyramid spec (§3, decisions 14 and 16, the cap note) and the
logging-as-you-go spec. Tests: fixtures that used `project` now use `attempt`; new cases in
pyramid, stats, sessions, goals, coach and a new `storageOutcome.test.js` for the load remap —
937 pass. The coach's fixed terminology was left alone: a first attempt to explain *repeat* there
broke the "summary is cheaper than full" test by a few characters, so the explanation rides the
climb line only when a repeat occurs.
