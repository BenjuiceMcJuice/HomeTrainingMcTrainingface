## BTL-B44 — bottom tabs floating

**Merged 2026-09-18 on Ben's word — *"Push to main."* Not seen on a phone first; the check below still applies to the live site.**

**Cause.** The mobile bottom nav is `position: fixed` with `backdrop-filter: blur(12px)`.
WebKit has a long-standing compositing bug where a fixed element carrying a backdrop blur is
painted at a stale scroll offset after the document's height changes underneath it — a widget
collapsing or expanding, a sheet closing, the keyboard dismissing. The page scrolls, the bar
does not follow, and the blur layer smears the content it used to sit over. That is exactly the
screenshot: bar mid-page, whited-out band beneath it, "V4 / V5" rows showing through the edge.

**Fix — `src/components/layout/Nav.jsx`.**
- `backdropFilter` removed from the bottom nav. Background is now solid `#ffffff` instead of
  92% white; there was almost nothing to see through it anyway.
- `transform: translateZ(0)` on the bar so it has its own compositing layer and is repositioned
  with the viewport rather than repainted with the page. A transform on the fixed element itself
  does not break its fixed positioning — only a transform on an ancestor does.
- The sticky top header and the desktop nav keep their blur — the bug is specific to `fixed`.
- Comment in the JSX says why, so nobody adds the blur back for looks.
- Cache v33 → v34 so installed phones drop the old bundle.

**668 tests, 0 lint errors, build clean.** The bug is intermittent and only reproduces on iOS, so
it is not verified on a phone. Check on the preview deploy: open the Dashboard, expand and collapse
the Boulder widget a few times mid-scroll, open and close a log sheet, and the bar should stay on
the bottom edge throughout.

Released the same day on Ben's instruction.

## Friends see the pyramid

Ben, on the friends page: *"Can we review what we share with friends. Perhaps the climbing
pyramid as a general view and/or the chart also with an all time / last 30 days perhaps or just
last 30 days maybe? And owned / best grade."* Then: *"Happy to go with your recommendations for
now. It's climbing focused only."*

**On a branch, not merged** — `claude/friends-info-sharing-review-rrfmpf`. A change to a screen
that already works, so it waits for Ben's word.

**What was wrong first.** The friend detail view had an *All Time / Last 90 Days* toggle. Since
Q3 (2026-09-13) the *All Time* tab showed Base, Best and Flash overlaid from the 180-day
pyramid, so it was not all time. The *Last 90 Days* tab read `boulderCurrent` / `ropeCurrent`,
the older 90-day stats that were never given a base, so `ownedGrade` fell back to the retired
consistent grade and the big number changed meaning between the two tabs. The data-honesty spec
still listed this surface as its weakest, and it was right.

**Decided.** One window, the pyramid's 180 days — not 30 (a base needs eight credited sends at
one grade; a month rarely holds that, and it would be a third window the app reads nowhere else)
and not all time (a base is a statement about the window). Owned and best were already shared;
what was missing was the pyramid behind them and the basis.

**Built.**
- `lib/goals.js` — `impliedGradeTarget(type, reading)`: the next rung above the base, or above
  the project with no base. Lifted out of `Dashboard.jsx`'s `readPyramid` so the profile and
  the Dashboard cannot pick different targets. `buildPublicProfileWithBase` now adds to each
  level: `pyramid` (`target`, `tiers` as `{grade, need, have, met}`, `label`, `sessionCount`,
  `windowDays`, `basis`), `grades` (`{attempts, sends, flashes}` per grade over the window) and
  `allTimeBest` (the `stats.js` all-time hardest send, read before the window's `project`
  overwrites the key). Older keys stay.
- `pages/Dashboard.jsx` — calls the helper; `V_GRADES` / `FRENCH_GRADES` imports dropped.
- `components/friends/FriendsScreen.jsx` — the toggle is gone. One `DisciplineCard` per
  discipline: level badge, the grade owned, Best / Flash / All-time (all-time only when it
  differs from the window's best), the basis line top right, then `PyramidChart` (compact,
  "Base for V5 · next up") and `GradeChart` + `Legend`, the Dashboard's own components. A
  friend whose profile has no `pyramid` key reads *Pyramid not shared yet — their app needs to
  sync on the latest version*. Recent sessions unchanged.
- Tests: the published tiers and their shape, per-grade counts, all-time best surviving the
  overlay, an empty window publishing an empty pyramid with its basis, and the target helper.
- Cache v34 → v35.
- Specs: the pyramid spec's §6 *Friends: not done* line and decision-table row 4 were both stale
  since 2026-09-13 — fixed. The honesty spec's §6 row for friends updated.

**Left open.** BTL-B31 grows: the privacy copy must list what friends now see, including
per-grade attempt counts, which is new disclosure. BTL-B45: check on a phone.

**675 tests, 0 lint errors (13 warnings, all pre-existing), build clean.** Not seen running —
