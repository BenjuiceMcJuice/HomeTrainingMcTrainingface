## P1 — the first impression and the broken things (BTL-B130 to B137)

Branch `claude/p1-review-fixes`.

- **BTL-B130 — the empty Dashboard.** `Dashboard.jsx` renders no Shameometer until the log holds
  anything at all (a session, a drink, a schedule entry or a sealed week) and no alcohol card until
  a drink has been logged; `calcAlcoholFreeStreak` returns zero on an empty log instead of walking
  back to the 3,650-day safety cap; the "Start logging sessions" hint moves above the widgets;
  wrappers of widgets that render nothing are `empty:hidden`, so the seven self-hiding widgets no
  longer leave a quarter-screen of gaps. The comment on the Shameometer saying it *always* renders
  is now about an empty week, not an empty log.
- **BTL-B131 — the name prompt.** `components/auth/NamePrompt.jsx`: one field, one Save, no
  backdrop tap. `App.jsx` opens it instead of the Settings sheet on first sign-in.
- **BTL-B132 — the stepper.** `NumericStepper` keeps a typing draft and commits the value only
  when the draft is a number inside the range, clamping on blur. Before, every keystroke outside
  the range was refused, so "15" could not be typed into a field with a minimum of 5.
- **BTL-B133 — an unchanged weigh-in.** Log › Health refuses only the value today already holds.
- **BTL-B134 — assisted hang weight.** The session detail sheet and the coach context read the
  mode first and the sign second (`hangLoadLabel`, `hangLoad`); an assisted hang read as bodyweight
  because both tested `weightKg > 0` and the loggers store assisted weight negative.
- **BTL-B135 — the schedule follows a routine.** `useRoutines` and `useHangRoutines` save the
  schedule with the routines: a delete removes the routine's entries, a rename updates
  `routineName`. Pure helpers `scheduleWithoutRoutine` / `scheduleWithRoutineName` in
  `lib/reminders.js`, tested.
- **BTL-B136 — the goal sheet refuses what the log already meets, for every type.** A run target
  at or under the best run, or a weight target equal to today's weight, used to auto-achieve on the
  first render after Save; the refusal ran for grade goals only. The sheet now asks `goalEvidence`
  with today's reading as the candidate's `startValue`, which is what `addGoal` would store.
- **BTL-B137 — Export JSON** leaves out `groqKey`, `calendarFeed` and `pushSub`. Import never read
  them.

**Seen running** in Chromium at 390 × 844 with Firebase faked, scripted: the name prompt on an

unchanged 77.5 logged for today and refused a second time; "15" typed into the cardio duration
