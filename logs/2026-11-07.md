# 2026-11-07

## New built-ins never reached a signed-in account (BTL-B159)

Ben, with a screenshot of Plan › Exercises searching *Pron* — only Wrist Pronation/Supination:
*"Can't see the exercise."* The three from BTL-B158 were missing on his phone.

Cause, in `App.jsx`'s load effect: `seedDefaultExercises()` / `seedDefaultRoutines()` add missing
built-ins to localStorage, then `pullFromFirestore` runs and — since the cloud `updatedAt` is
nearly always newer than the profile's (the BTL-B37 note in `storage.js` says as much) —
`mergeFromCloud` replaces `il_exercises` and `il_routines` with the cloud copy. The seeded ids
never got synced, so they were wiped every load. Yesterday's harness check missed it: it set
localStorage directly and the fake Firestore had no user doc, so no merge ran.

Fix: `mergeCloudAndSeed()` in `App.jsx` — the merge followed by both seeders — at the two places
the effect merges. Seeders only add missing ids and purge retired ones, so edits are untouched.
The added ids reach the cloud with the next change, like any local edit.

Reproduced in the harness with `fakeFirestore` holding a `users/dev-uid` doc whose exercises lack
e102–e104 and whose `updatedAt` is newer than the local profile: before the fix 96 exercises after
load, none of the three; after, 99 and Prone Y-Raise found by search. Build, 941 tests, lint at its
13-warning baseline. Cache v94 → v95.

A fix to live behaviour, so merged without asking (CLAUDE.md, *When to merge without asking*).

## Lock-off Hold's note corrected (BTL-B160)

The e104 note from BTL-B158 said 90 degrees is "chin level with the bar". Wrong: at 90 degrees the
upper arms are level with the floor and the bar is about eye height; chin over the bar is the top
hold. Noticed while explaining lock-offs to Ben; he said *"Please."* to the fix.

- `defaultExercises.js` — new note: the 90-degree position, then easier (top) and harder
  (120 degrees, one arm).
- A seeded built-in is the athlete's own copy from then on, so changing the default alone would not
  reach Ben. New `SUPERSEDED_NOTES` (id → old texts); `seedDefaultExercises` swaps in the current
  note only where the stored note equals an old text exactly. Edits are left alone. Runs at both
  seeding points, including after the cloud merge (BTL-B159).
- Harness, through a cloud load: old text → new note, defaultDuration 7 kept; an edited note kept.
- Build, 941 tests, lint at baseline. Cache v95 → v96. Merged to `main`.
