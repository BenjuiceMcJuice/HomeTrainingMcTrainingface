## BTL-B103 — coach and low-intensity hangboard (branch `claude/emil-hangboard-clarity-pi88s1`)

Ben, with a Geoff analysis attached: *"The sub max repeaters are very low intensity (40% max
weight) but groq doesn't seem to know this."* Geoff called the daily Sub-Max Repeaters (Emil
Abrahamsson's protocol) "finger-and-ankle overload", said rest averaged under two days, and said
effort was stuck at 2–3/5.

Why: the prompt carried each hang session as six grips `1x6` with no load, no timing and no word
of what the routine was for; every hang day counted in the rest gap; one effort average across
every type let the 2/5 hangs drag the climbing figure down.

Decisions (Ben):
- No new intensity field — *session feel* is required on every hang save and is what the
  session actually was, so it is the signal. Feel 1–2 = background, 3+ = load.
- Shameometer untouched — it rewards turning up, and a sub-max session is turning up.

Built, `src/lib/coach.js` only (+ `Coach.jsx` passes `data.routines`):
- `BACKGROUND_HANG_MAX = 2`, `isBackgroundHang(s)`.
- Hang sessions at feel ≤ 2 tagged `LOW-INTENSITY` in the full and summary contexts.
- 30-day line: `hang:3 (3 low-intensity background)`.
- `Avg effort by type: climb 3.0/5, hang 2.0/5` replaces the single average.
- Rest gap leaves out background hangs as well as cardio.
- `HANG ROUTINES (what each is for)` — first sentence of each used routine's description.
- Grips show `+10kg` / `-20kg assisted` when not bodyweight.
- A `HANGBOARD:` note in the instructions, sent only when the window has hang sessions — sending
  it always pushed the summary context past its 75%-of-full test.

Tests: 8 new in `coach.test.js`; 860 pass, lint clean on the touched files, build ok.

Noticed, not changed: BTL-B13 (*prune the schedule — Sub-Max Repeaters is 7 days/wk*) reads
against today's framing; daily is the protocol. Ben's call.

### Found: sign-in wiped unsent changes (BTL-B37's cause)

Harness: a climb tapped 150 ms before a reload was gone after it. `App.jsx` replaces local with
the cloud copy whenever the cloud doc's `updatedAt` > the profile's (nearly always), and
`getFirestore` has no offline cache, so unsent writes live in memory only — true today for any
session saved with no signal and the app closed. Fix: `Storage.markUnsynced(uid)` on every
`setDataAndSync`, cleared by `syncToFirestore` when its write lands (unless a newer mark came in);
`hasUnsynced(uid)` on sign-in → push instead of pull. The uid guards a second account on a
shared device (sign-out leaves the log). 3 tests in `storageUnsynced.test.js`. Reload at 0 / 150
/ 1500 ms now keeps the climb.

Harness run (15 steps) all pass: first tap saves with null feel; second updates; removing the
last deletes; notes + venue + a climb tapped straight after typing all kept; reload → card with
*Feel not set* and Finish; Continue saves on tap; Back → card; Dashboard row → Finish ends it,
row and card gone; Done with feel ends it; Done without feel asks, second Done ends with null;
