## BTL-B120 — the comp poster as a PDF

Ben, with a screenshot of Manage's join card: *"Can we have the option to save this as a pdf so it
can be downloaded and printed?"*

**Poster (PDF)** beside *Copy link* on Manage › Join code. One A4 page: *BetaLog · Competition*,
the name (wrapped to three lines), type · date, start · venue, the editor's *notes for the poster*
(three lines), the QR, *Scan to join, or enter the code*, the code in large monospace, the link.

`src/lib/compPoster.js` writes the PDF by hand rather than adding a library: one page, the
standard fonts (Helvetica, Helvetica-Bold, Courier-Bold — nothing embedded, every reader has
them) with their AFM widths for centring and wrapping, and the QR drawn as filled squares from
`qrcode-generator`'s modules, so it is vector and prints sharp at any size. The QR shrinks from
340 pt when the text above runs long so the page never overflows. Text is WinAnsi: a character
the fonts lack prints `?`. Download goes through the same blob link as the CSV export (shared
`download()` in `CompManage.jsx`). 11 tests in `compPoster.test.js` — the xref offsets, the stream
length, escaping, wrapping, the long-text layout. Rendered with `pdftoppm` and looked at; clicked
through in Chromium at 390 px with Firebase faked (`dev/`), file `autumn-bloc-party-poster.pdf`.
Guide updated. Cache v80.

## BTL-B123 — Google sign-in in the installed iPhone app

Ben, with a photo of the login screen from a friend's phone: *"My mate gets this when saving to
Home Screen. He could sign in fine from safari."* The red line was the app's own: `LoginScreen.jsx`
refused Google whenever it ran standalone and told the climber to sign in in Safari, on the
belief (in the comment) that the installed app shares Safari's localStorage. It doesn't — an iOS
home-screen app has its own storage — so the advice could never work. Ben: *"Build it now. Can you
do the lot?? Test very well please."*

The fix is Firebase's documented one for partitioned storage ("proxy auth requests to
firebaseapp.com"):

- `functions/__/auth/[[path]].js` — a Pages Function passing `/__/auth/*` to
  `betalog-340b3.firebaseapp.com`: path, query, method, body, headers less Host and Cloudflare's;
  redirects handed back, not followed; a redirect to the handler itself kept on our origin; 502,
  uncached, when upstream is down. Only `/__/auth/*` runs it (`_routes.json` from `wrangler`).
- `src/lib/googleSignIn.js` (new, pure) — `authDomainFor(host)`: the host itself for
  `PROXIED_AUTH_HOSTS` (betalog.co.uk and this branch's preview), firebaseapp.com elsewhere, so
  hosts Google doesn't know keep working. `googleFlow`: popup in a tab, redirect in the installed
  app on a proxied host, *blocked* (with a message, no hang) in the installed app elsewhere. A
  localStorage note marks a redirect under way so `getRedirectResult` runs only on the load that
  returns from one (firebase.js's comment on why). Error codes in words.
- `LoginScreen.jsx` — the redirect flow; *Finishing sign-in…* on the way back; a lost state says
  *Google sign-in didn't finish* and opens email login.
- Deleting a Google account in the installed app — the popup reauth can't come back there either.
  It now accepts a sign-in from the last 3 minutes (`signedInRecently`, under Firebase's 5 so the
  deletion has time to run) and otherwise says *sign out, sign back in with Google, come straight
  back*, before anything is deleted.
- `sw.js` leaves `/__/` to the network — a cache-first handler page would break sign-in. Cache v81.
- The guide (sign-in and deleting), the help spec's note, the deployment guide (the Function and
  the two console settings each proxied host needs), CLAUDE.md's file list.

Testing: 34 new unit tests (`googleSignIn`, `authProxy`, `accountDeletion`), 929 in all, pass;
lint 13 warnings as before; build passes. The proxy under `wrangler pages dev` (workerd) against a
local stand-in for firebaseapp.com: GET with query, POST body, Host and cf- headers dropped, a 302
to Google passed through, a 302 to itself rewritten to our origin, other routes still the SPA. In
Chromium at 390 px with Firebase faked and `betalog.co.uk` mapped to localhost, standalone
emulated: redirect → back → signed in, read once and not again on reload; lost state; network
error; cancel; blocked on localhost; a tab still uses the popup; the three deletion cases. The real
production build with the real Firebase SDK, standalone on `betalog.co.uk`: tapping Google navigates
to `https://betalog.co.uk/__/auth/handler?…authType=signInViaRedirect…`. Not testable from here:
the round trip through Google and back (no network to Google) and, above all, an iPhone.
