## Widget system — phase A: the shell, properly

First phase of `docs/specs/betalog_widget_system_spec.md`. Scope is exactly what the spec gives
phase A: make the whole header the collapse control, move the timeframe chips out of the headers and
into the bodies, and restore the calendar's full-width header. No new data, no new widgets, none of
the three open decisions touched.

### The whole header row is the tap target

`WidgetShell.jsx` — the row is now a real `<button>` with the header content inside it and the
chevron as a decorative `<span>`; `min-h-[44px]` puts it over the touch-target threshold that the
old ~24px chevron missed. Hover moves to `group-hover` on the chevron, so nothing looks different
until you tap.

In edit mode the row renders as a plain `<div>` again — same rule as before, a tap meant for the
drag handle must not fold the card.

This restores what `ActivityCalendar` had before declutter phase 2 replaced its full-row toggle with
the small chevron, and it gives the same affordance to the other four collapsible widgets rather than
only putting the regression back.

### Chips moved into the bodies

A `<button>` header means no buttons in the header — nested buttons are invalid HTML and ambiguous
to tap. Two cards had them:

- **Cardio** — the `7d / 90d` chips now head the body. The header keeps the count and total duration
  and gains a plain-text window label (`2 sessions 7d`), so a collapsed card still says which window
  its number covers.
- **Alcohol** — the chips move off the timeline's value row onto their own row at the top of the
  body, matching the anatomy diagram and the cardio card. The `-1 vs prev` delta keeps its
  right-hand slot.

`LevelCard` already worked this way, so it is untouched; the calendar's month stepper was already in
its body.

**One copy fix on the way past:** the cardio card said "No sessions this week" whatever the window
was selected — it now reads "No sessions in the last 7d/90d".

Dropped the unused `ChevronDown`/`ChevronUp` imports from `ActivityCalendar`, left over from before
it used `WidgetShell`.

## Widget system — phase B: one vocabulary

Ben chose **per-card, persisted** for the window question, so phase B was buildable. Built on
`claude/widget-thingy-phase-a-1hy78q` — the branch name is now a phase behind, but it is the
designated branch for this session, so the work stays on it.

### Windows are a persisted, per-card thing

New `src/lib/widgetWindow.js`, deliberately shaped like `widgetCollapse.js`: `WINDOW_OPTIONS` per
card, `WINDOW_DEFAULTS` (90d everywhere), `getWindow`, `setWindow`, `windowDays`. State lives in
`profile.widgetWindow`, beside `widgetCollapsed`, so it syncs across devices for free.
`hooks/useWidgetWindow.js` is the component-facing wrapper.

`getWindow` validates the stored value against what the card currently offers and falls back to the
default when it does not match. That is not defensive padding — cardio's `7d` chip disappears in
this phase, and anyone who had it selected has a stored `7d` that no longer exists.

14 unit tests in `src/lib/__tests__/widgetWindow.test.js`.

### One vocabulary

- **Cardio** — `7d / 90d` becomes `30d / 90d / 12m`, defaulting to 90d rather than 7d. Its window
  now comes from `filterSessionsByDays` like everywhere else, not `daysAgo(days - 1)`.
- **Alcohol** — `30d / 12w / 12m` becomes `30d / 90d / 12m`, and the chips now mean *window*, not
  bucket size. The card derives granularity: 30d → daily bars, 90d → weekly, 12m → monthly, via a
  new `ALCOHOL_WINDOW_MODE` map in `stats.js`.
- **Level cards ×2** — chips unchanged (`90d / All time`, a different question), but the choice
  now persists instead of resetting on every reload.
- **Gym** — `daysAgo(89)` replaced with `filterSessionsByDays(…, 90)`. No chips: it has no body to
  put them in until phase D.

**Weekly buckets went 12 → 13.** A chip that says `90d` has to cover 90 days, and 12 Monday-aligned
weeks only cover 84. Seven timeline tests moved index (the current bucket is now 12, not 11) and the
average-per-week expectation changed with the longer window — all in `stats.test.js`.

**Cardio's visibility gate changed** from "any cardio in the last 90 days" to "any in the last 12
months". Offering a 12m chip while hiding the card from anyone without a recent session would have
hidden it from exactly the people that chip is for. Chips for empty windows render disabled, as the
`7d` chip already did.
