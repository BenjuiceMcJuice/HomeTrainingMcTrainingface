# 2026-04-12 — Work Log

## What we did

### Gym integration data model (Phase 2 — Route Board)
- **Designed full data model** for gym centre route management:
  - `Gym` — organisation (e.g. Redpoint)
  - `Centre` — physical climbing wall within a gym
  - `CentreStaff` — role-based access (admin / setter) per centre
  - `Route` — a boulder problem or rope route on the wall, with full lifecycle (active → retired, never deleted)
- **Firestore structure:** `gyms/{gymId}/centres/{centreId}/routes/{routeId}` and `staff/{userId}`
- **MVP access model:** routes readable by any authenticated user (open read), writable only by staff. No centre membership linking needed. Lock down later if needed.
- **Climb ↔ Route link:** existing `Climb` fields (`routeId`, `gymId`, `centreId`) already support this — just populate them when logging against a centre route.

### Banked ideas
- **Client-side friend notifications** — on climb session save, write notification doc to each friend's Firestore inbox. Display on next app open. Zero cost, no Blaze/FCM needed.
- **Leaderboard page** — standalone `/leaderboard` URL, button on Dashboard. Deferred until more users exist.
