# 2026-07-05

## Identity & naming spec

**Files changed:** `docs/specs/betalog_identity_naming_spec.md` (new), `docs/strategy/betalog_vision.md`, `CLAUDE.md`

### Context
Spotted that the same Firebase user renders differently per screen: the admin users
list shows the Google `authDisplayName` ("David Richardson") while the friend/public
profile shows the typed `athleteProfile.name` ("Dave of Knowle West"). No shared
resolver, no authoritative field. Rock Gym Pro import will add a third name source.

### Changes
- Wrote `docs/specs/betalog_identity_naming_spec.md`. Separates four concepts (account
  ID / unique username handle / non-unique display name / private legal name), defines
  a single `resolveDisplayName()` resolver to be used by every surface, reuses the
  existing `friendCodes` pattern for username uniqueness (`usernames/{handle} → uid`),
  and specifies RGP reconciliation (email join key, non-destructive `sources.rgp.*`,
  imported data only seeds empty fields). Key call: unique **username**, non-unique
  **display name** (two Daves can both show "Dave"). Phased so the resolver ships first
  with no migration.
- Added an Identity & naming entry to the Platform backlog and a Decision Log row in
  `betalog_vision.md`; bumped its "Last updated" to July 2026.
- Added the spec to the Documentation Index in `CLAUDE.md`.

### Notes
This is docs only — no code changed yet. Phase 1 (the resolver + typedef fields) is the
recommended next implementation step; it fixes the visible inconsistency without a schema
migration.

## Distance units — default to miles + regional toggle

**Files changed:** `betalog-react/src/lib/utils.js`, `src/components/dashboard/CardioStatsCard.jsx`,
`src/pages/Dashboard.jsx`, `src/components/layout/SettingsSheet.jsx`,
`src/components/log/CardioLogSheet.jsx`, `src/lib/types.js`

### Context
Dashboard cardio card showed distance in km ("Walk 3 · 20.8 km") while History and the
log sheet used miles ("3.2 miles"). `fmtDist` hardcoded km; logging already defaulted to
miles, so only the Dashboard was off. User wanted miles as the default plus a regional
units toggle.

### Changes
- `fmtDist(km, units='miles')` is now unit-aware — converts km→mi (÷1.609) or shows km.
  Default is miles, so the Dashboard cardio summary now reads "12.9 mi" instead of "20.8 km".
- Added `athleteProfile.units` ('miles' | 'km', default 'miles'). Documented in `types.js`.
- `CardioStatsCard` takes a `units` prop (from `profile.units`) for the activity distance
  summary. Cardio **goal** rows are left explicit `'km'` — goals are entered in km in
  GoalsSection, so their display is unchanged (avoids an entry/display mismatch).
- Settings sheet: added a Miles / Kilometres segmented toggle, persisted on the profile
  (syncs to Firestore like the rest of the profile).
- `CardioLogSheet` default input unit now follows the preference via `defaultUnitFor()`
  (swim stays lengths), so the toggle is regional for input too. History still shows the
  literal logged unit — faithful to what was entered.

### Notes
- Build passes. Test suite: 4 pre-existing failures in `stats.test.js` (getPaceMET MET
  bands) confirmed present on the unmodified tree — unrelated to this change.
- Known follow-up: cardio goals remain km-based end to end (entry + display). If a
  miles-preference user has an active cardio goal, the goal row shows km while the activity
  summary shows miles. Unifying goals onto the units preference is a separate task.
