# 2026-06-02

## Weight edit stepper — decimal direct entry

Fixed a bug where typing a value directly into the Edit Weigh-in stepper truncated decimals (e.g. "93.2" → 93). Root cause: `NumericStepper.handleChange` used `parseInt`, and `inputMode="numeric"` showed an integer-only keyboard on mobile.

Fix: NumericStepper auto-detects fractional steps (`step % 1 !== 0`) and uses `parseFloat` + `inputMode="decimal"` + decimal-friendly `pattern` in that case. Integer fields (reps, sets, duration) unaffected.

Files changed: `src/components/ui/NumericStepper.jsx`

## Code review + 8 bug fixes

Full `/code-review` pass across the codebase (high effort, 7 angles). 9 findings — 8 fixed in one commit.

### Fixes applied

**Calorie estimates wrong for moderate effort (`stats.js:384`)**
`getMETRange` effort=2 used `table[1]` (Easy MET) as the low bound instead of `table[2]` (Moderate). Every cardio session logged at Moderate returned the same calorie range as Easy. Fixed: effort=2 now uses `low=table[2], high=table[3] || table[2]*1.1`.

**Empty date corrupts weight history (`WeightEditSheet.jsx`)**
Clearing the date field and tapping Save stored an empty string as the entry date, which sorts before all ISO dates and breaks the weight chart. Fixed: `handleSave` returns early if `editDate` is empty; Save button disabled when date is cleared.

**Negative cardio distances stored (`CardioLogSheet.jsx:144`)**
`parseFloat` on the distance input had no range guard — typing `-5` stored `-5 lengths` and negative calorie estimates. Fixed: `parsedQty` clamped to `Math.max(0, rawQty)`; NaN values become null.

**Goal achievement never fires on session edits (`useGoals.js:123`)**
The achievement `useEffect` depended on `[sessions.length, weightLog.length]` so editing a climb grade (same session count) never triggered re-check. Fixed: dependency array changed to `[sessions, weightLog]`.

**Legacy weight log key never migrated (`storage.js:313`)**
`il_weight_log` (old key) was read as a fallback on every load but never written to `il_weightLog`, so the migration never completed. If `il_weightLog` was later written as empty, old data would silently disappear. Fixed: on first load, data is written to `il_weightLog` and the old key deleted.

**Friend code collision retry didn't check the new code (`storage.js:497`)**
Single-retry path generated a new code but immediately called `setDoc` without re-checking it for collision. Fixed: replaced with a recursive loop (up to 5 attempts), each checking the new code before writing.

**`syncToFirestore` re-parsed all localStorage on every save (`storage.js:410`)**
`syncToFirestore` called `Storage.load()` internally, re-parsing all collections from localStorage on every mutation. No real debounce — rapid saves each fired an independent full-cost Firestore write. Fixed: function now accepts a pre-computed `data` parameter (falls back to `Storage.load()` if omitted); `setDataAndSync` in App.jsx passes `next` directly and uses a proper `clearTimeout` debounce (300ms).

**Firebase sync errors were silent (`storage.js:411` / `App.jsx`)**
Firestore write failures were only logged to `console.warn`. Fixed: `syncToFirestore` accepts an `onError` callback; App.jsx passes a handler that sets `syncFailed` state, showing a dismissible red "Sync failed" banner.

Files changed: `src/lib/stats.js`, `src/hooks/useGoals.js`, `src/components/log/WeightEditSheet.jsx`, `src/components/log/CardioLogSheet.jsx`, `src/lib/storage.js`, `src/App.jsx`

## Calorie calculator overhaul

Four-stage improvement to cardio calorie estimates, all shipped to prod.

### 1. Corrected swim MET values
Updated `MET_SWIM` and `MET_CARDIO.swim` to match the Compendium of Physical Activities:
- Breaststroke hard: 6.8 → 7.0; easy: 4.8 → 5.3
- Front crawl hard: 8.3 → 9.8; easy: 4.5 → 5.8
- Backstroke hard: 7.5 → 8.0; easy: 4.5 → 4.8
- Butterfly hard: 11.0 → 13.8; easy: 7.0 → 8.0

### 2. Stamp calories at save time
`SessionDetailSheet` was re-calculating calories from current weight on every open, meaning weight changes retroactively altered old session estimates. Fixed: display now uses stored `cardioKcalLow`/`cardioKcalHigh` stamps when present; recalculation only happens for legacy sessions without stamps. `CalorieBalanceCard` and `CardioStatsCard` already used stamps correctly.

### 3. Pace-based MET for non-swim cardio (run/cycle/row/walk)
When both distance and duration are logged, derive MET from actual pace (m/min) using lookup tables rather than the subjective effort label. Added `PACE_MET` tables and `getPaceMET()` to `stats.js`. Also added `deriveSessionMetres()` helper to convert session quantity/unit/poolLength to metres. Applied to all calorie calculation sites.

### 4. Distance-based kcal/m for swimming
Deep research into swimming exercise physiology (Pendergast et al. 1977, Zamparo & Capelli 2011) showed that at recreational paces (0.5–1.0 m/s), energy cost per metre is approximately speed-independent. Switched swimming to a weight-adjusted per-metre formula:
- Breaststroke: 0.30 kcal/m per 70 kg
- Front crawl: 0.20 kcal/m
- Backstroke: 0.22 kcal/m
- Butterfly: 0.44 kcal/m
- General: 0.25 kcal/m

Calibrated against Garmin's ~25–30 kcal/100 m user reports. Same distance now gives the same calorie estimate regardless of duration. Run/cycle/row/walk keep pace-based MET × duration (correct for those activities).

Added `getSwimKcalRange()` to `stats.js` and updated all calorie calculation sites (CardioLogSheet, SessionDetailSheet, History, CalorieBalanceCard, CardioStatsCard).
